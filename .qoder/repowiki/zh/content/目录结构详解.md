## 目录结构

本项目采用模块化、分层清晰的目录结构，遵循 Next.js App Router 的最佳实践，确保功能职责明确、代码可维护性强。各主要目录及其子目录的设计逻辑如下：

### app/ 目录：页面路由与布局管理
`app/` 目录是 Next.js 应用的核心，负责页面路由、布局和 API 路由的组织。

#### (user)/ 子目录：用户端页面路由
位于 `app/(user)/` 的括号表示该目录为**路由组**，不会出现在 URL 路径中，仅用于逻辑分组。该目录下包含普通用户的全部功能页面：
- `article/[id]/page.tsx`：文章阅读页，通过动态路由 `[id]` 加载指定文章
- `library/page.tsx`：文章库页面，展示所有可读文章
- `stats/page.tsx`：学习统计页面，显示用户学习进度与成就
- `layout.tsx`：用户端通用布局，包含顶部导航栏和移动端底部标签栏，支持响应式设计

该布局通过 `usePathname` 和 `useRouter` 实现导航高亮与页面跳转，并根据用户角色（通过 `session.user.role` 判断）在导航栏中动态显示“管理后台”入口。

**Section sources**
- [app/(user)/layout.tsx](file://app/(user)/layout.tsx)

#### admin/ 子目录：管理员页面路由
`app/admin/` 目录对应管理员专用功能，其 URL 路径为 `/admin`，包含：
- `articles/`：文章管理，支持查看、新建、编辑文章
- `users/`：用户管理，支持查看和修改用户信息
- `page.tsx` 和 `layout.tsx`：管理员首页与布局组件

管理员布局通过 `<AdminLayout>` 组件实现，该组件位于 `components/AdminLayout.tsx`，提供侧边栏导航和权限控制。

**Section sources**
- [app/admin/layout.tsx](file://app/admin/layout.tsx)

#### api/ 目录：RESTful API 端点组织
`app/api/` 目录下的 `route.ts` 文件用于定义 API 路由，采用嵌套路由结构实现功能分组：
- `admin/articles/route.ts`：管理员文章管理 API，支持 `GET`（获取列表）和 `POST`（创建文章），并集成 `requireAdmin` 权限校验
- `articles/route.ts`：公开文章列表 API，供前端获取所有文章数据，支持数据库回退到 `MOCK_ARTICLES`
- `auth/[...nextauth]/route.ts`：NextAuth 认证路由，处理登录、会话等逻辑
- `cos/upload/route.ts`：腾讯云 COS 文件上传接口，仅管理员可调用，接收 `FormData` 并返回上传后的文件 URL

API 路由通过 `NextResponse` 返回 JSON 数据，并统一处理错误与状态码。

### components/ 目录：可复用 UI 组件
该目录存放所有可复用的 React 组件，设计原则为**单一职责、高内聚、低耦合**。

#### ArticleReader 组件
`components/ArticleReader.tsx` 是核心阅读组件，支持三种视图模式（英文、中文、中英对照）。其设计特点包括：
- 使用 `@bytemd/react` 渲染 Markdown 内容，并通过 `splitIntoParagraphs` 智能分割段落
- 集成 `AudioPlayer`，实现音频播放时自动高亮对应段落（基于单词数比例分配时间）
- 提供“标记为已完成”按钮，触发学习进度更新

**Section sources**
- [components/ArticleReader.tsx](file://components/ArticleReader.tsx)

#### AudioPlayer 组件
`components/AudioPlayer.tsx` 封装原生 `<audio>` 元素，提供播放控制、进度条、时间显示和错误处理。支持通过 `onTimeUpdate` 回调通知父组件当前播放时间，实现与 `ArticleReader` 的联动。

**Section sources**
- [components/AudioPlayer.tsx](file://components/AudioPlayer.tsx)

#### CosUploader 组件
`components/CosUploader.tsx` 为管理员提供音频文件上传界面，封装了文件选择、类型验证、上传进度显示和音频时长提取功能。通过 `XMLHttpRequest` 调用 `/api/cos/upload` 接口完成上传，并支持清除已上传文件。

**Section sources**
- [components/CosUploader.tsx](file://components/CosUploader.tsx)

### lib/ 目录：工具函数与共享逻辑
`lib/` 目录存放跨组件共享的工具函数和配置。

#### auth.ts：认证逻辑封装
`lib/auth.ts` 定义了 `authOptions` 配置对象，集成 `next-auth` 的凭据认证，并在 `jwt` 和 `session` 回调中注入用户角色（`role`）。同时导出 `requireAdmin` 函数，用于在 API 路由中校验管理员权限，返回标准化的错误响应。

**Section sources**
- [lib/auth.ts](file://lib/auth.ts)

#### prisma.ts：数据库连接管理
`lib/prisma.ts` 封装 Prisma Client 实例，避免在开发环境下重复创建连接。通过 `globalForPrisma` 实现热重载优化，并注册 `beforeExit` 事件确保连接优雅关闭。同时包含连接健康检查逻辑。

**Section sources**
- [lib/prisma.ts](file://lib/prisma.ts)

### prisma/ 目录：数据模型与迁移
#### schema.prisma：数据模型定义
`prisma/schema.prisma` 使用 Prisma DSL 定义了三个核心模型：
- `User`：用户信息，包含邮箱、密码、姓名、角色（默认为 `user`）等字段
- `UserProgress`：用户学习进度，与 `User` 一对一关联，存储完成文章列表、统计数据、徽章等
- `Article`：文章内容，包含中英文标题、摘要、正文（JSON 格式）、难度、时长、音频 URL 等

模型间通过 `@relation` 建立关联，并使用 `@@map` 指定数据库表名。

**Section sources**
- [prisma/schema.prisma](file://prisma/schema.prisma)

#### migrations/ 目录：数据库变更管理
`prisma/migrations/` 目录存放数据库迁移脚本，每个迁移包含一个 SQL 文件，记录表结构的变更历史。通过 `prisma migrate dev` 命令可同步模型变更到数据库。

### services/ 目录：业务服务封装
`services/storageService.ts` 提供对后端 API 的封装，替代本地存储：
- `getArticles()`：获取文章列表
- `getProgress()`：获取用户学习进度
- `markArticleComplete()`：标记文章完成，触发进度更新
- `saveProgress()`：已废弃，进度由服务端自动保存

这些函数统一处理 `fetch` 请求、错误捕获和 JSON 解析，供 React 组件或上下文使用。

**Section sources**
- [services/storageService.ts](file://services/storageService.ts)

### contexts/ 目录：状态管理
`contexts/ProgressContext.tsx` 使用 React Context 管理用户学习进度状态。`ProgressProvider` 在用户登录后自动获取进度数据，并提供 `refreshProgress` 方法供手动刷新。`useProgress` Hook 用于在组件中安全地访问上下文。
